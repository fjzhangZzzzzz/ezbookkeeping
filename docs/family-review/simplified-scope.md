# 家庭自用简化版：已确认范围与维护方案

状态：这是已确认的产品范围和维护决策记录，不是当前实现状态或发布入口。当前实现、测试和发布以 [实施状态](implementation-status.md)、[发布规范](release-policy.md)、ADR 和 CI 为准。原技术尽调和安全证据继续保留。方案评审后已确认全部使用内置图标、固定家庭统计时区、负净支出图表降级和会话清理；首版关闭自动定时记账、保留普通手动模板已确认。

## 1. 产品目标与使用边界

一个实例服务一个固定家庭，最多10名成员。新SQLite数据库起步，不导入旧实例数据，不开发通用老版本迁移工具。以后若出现实际旧账，单独确认一次性导入范围。

每人独立账号；账户、交易、模板等原有个人功能继续归本人。家庭内所有成员可查看当前启用成员的交易、账户余额及附件，但只能新增、修改、删除自己的账户和交易。个人模式仍保留，指本人数据视图，不再代表家庭内隐私隔离。

家庭内完全互信，不设拥有者/成员/只读三级角色，不设逐笔分享、明细授权、私有分类或单独的附件授权。运维管理员是部署管理职责，不是新增一套应用内家庭角色。匿名访问仍拒绝；服务端继续保证本人写入边界。邀请码、注册审批、多家庭、跨家庭权限矩阵不开发。

成员由管理员预建和停用，不做邀请、加入、退出、家庭解散等自助页面。停用时禁止两种入口重新登录、吊销记账应用会话、从家庭总览移除，个人数据保留。家庭内私有信息已经可以被其他成员查看或下载，停用不能撤回其已保存的副本。

## 2. 记账、字典与统计

### 字典

全应用（包括账户和分类）仅使用内置图标，不引入个人自定义图标，不提供上传/选用个人图标的入口；服务端同时拒绝自定义图标引用。原有个人功能保留范围以此明确例外为准。

分类、标签及标签分组只有一套全家庭共享目录，成员都可维护。提供新增、改名、排序、隐藏；被引用项目不允许删除，不开发合并与历史交易批量替换。分类父子链、标签分组、隐藏行为一致处理；改名统一改变历史显示名称。删除未使用项目前也须检查模板、定时交易等全部引用，不能只查现有交易。

没有变更审批、完整审计查询、历史名称快照。共享字典改名是全家可见变更，不视作修改他人交易；系统仍不允许借修改分类或标签的接口改写他人交易。

实现优先使用单一实例共享目录；具体所有者字段/范围表示由实现设计确定，不能让共享数据依附某个可被停用或注销的普通成员。禁止复用某人的个人字典后直接忽略uid而不处理用户清理、初始化与注销逻辑。

### 内部往来

本人账户间转账沿用上游逻辑，家庭收支排除转出、转入和余额调整。跨成员转钱由双方分别记入固定的“家庭转出/转入”类别，家庭收支排除这两类。不自动匹配、不双向确认、不校验金额一致，不做AA或债务结算。

内部往来的统计语义必须绑定稳定的系统分类身份，不能依赖可改名文本。该分类身份不允许被普通隐藏/改名操作变成普通收支分类；其余显示与排序可复用普通目录。误分类由用户修正；系统不能宣称因此自动实现资金对账。

### 家庭统计

当前启用成员的全部历史直接纳入，没有加入起始日、历史授权或分享开关。停用某人后其全部贡献移除，历史报表随之变化，不提供永久固定的历史家庭报表。停用前需要留底可导出。

人民币为家庭统计唯一货币，首版不做历史汇率快照和外币折算。个人原有外币功能保留，家庭页如存在相关外币交易必须显式提示未计入，不能显示为完整总计。以账户实际币种确定是否纳入，不能误用用户默认显示币种。

家庭统计固定使用Asia/Shanghai，按该时区构造半开区间[开始时间,结束时间)，月界、趋势、页面与CSV均使用同一口径；个人模式维持原时区行为，不受家庭统计影响。

月度收入/支出/结余、支出分类占比、成员收支对比、最近十二个月趋势是四类核心统计。收入/支出排除余额调整、本人转账及明确的家庭内部往来；负支出作为退款抵减，负收入抵减收入。分类、成员与总额必须勾稽。当任一分类净支出为负，或总净支出小于等于0时，不绘制普通占比饼图，改显示保留正负金额的列表或条形图；不对退款取绝对值，不删去负分类来伪造占比。

家庭明细只做时间/成员筛选，支持查看当前成员账目、余额及附件；他人条目不可修改。个人写入入口保持self，不把整个现有个人接口批量改为多uid。家庭读取单独明确意图；返回全家明细已获用户允许，不再强制先后端匿名化聚合。

不做自定义报表和任意维度组合。不要求高并发或大规模压测，仍需分页、正确时间范围和不重复不漏记录。原transaction_time在跨成员间可能重复，家庭翻页不能照搬个人仅按时间递减的游标。

家庭导出仅收支汇总CSV，数字与页面一致、中文正常、文本字段防公式注入。个人完整导出沿用上游，不另外开发家庭明细Excel工作簿。共享字典对个人导出/导入的引用解析必须验证，不能将复用上游当作无需测试。

## 3. 登录与移动体验

公网HTTPS；账密和Pocket ID均可登录同一个本地账号。关闭公开注册和OAuth自动注册，由管理员建账号，成员首次通过本地密码确认绑定Pocket ID。

优先复用现有双登录与账号绑定能力：conf/ezbookkeeping.ini:550、:553；cmd/webserver.go:279、:292、:355；pkg/api/authorizations.go:448。OIDC绑定当前按邮箱/用户名处理（pkg/api/oauth2_authentications.go:218、pkg/models/user_external_auth.go:6），不是稳定主体键；实现阶段须核对Pocket ID实际claim、验证身份唯一性，不能启用“任意同邮箱自动接管”。账号改名/换邮箱后的重绑可人工维护，协议细节不再要求用户选择。

移动端使用现有持久会话与启动续期，沿用默认30天有效期、使用时续期，不开发永久会话。依据：conf/ezbookkeeping.ini:512、:516；src/lib/userstate.ts:207；src/MobileApp.vue:226；src/stores/token.ts:81。长时间未用、清除缓存、吊销或主动退出后需重登。

退出只退出记账应用，不做Pocket ID跨应用全局登出。设备丢失可吊销单设备或全部记账会话；停用成员必须同时处理本应用账号及会话，不能只在Pocket ID停用。Pocket ID临时不可用仍可用账密进入。

移动端优先完成完整闭环，验收普通手机浏览器及添加到主屏幕的真实场景：打开恢复登录、成功保存、失败提示、重试不重复、家庭页与成员切换。只做在线记账，不做离线队列/后台同步。网络失败不显示保存成功；实现可复用原有防重逻辑或补最小的幂等处理，不假定仅禁用按钮就可靠。

桌面端保留原有个人功能，家庭功能基本可用，不要求与移动端完全对等。AI、MCP、地图定位默认关闭，不纳入首版验收；不额外重写上游其他功能。

## 4. 产品维护边界

### 部署与备份

SQLite单一正式支持目标；不主动删除上游其他驱动，但不承诺其他数据库的改造适配和验收。不增加独立数据库服务。允许停写维护窗口、升级失败恢复备份，不开发不停机迁移或通用后台分离任务。

### 自动定时记账关闭，保留普通手动模板

上游支持用户设置重复交易模板，由服务器按计划直接生成真实收入、支出或本人账户间转账，不是提醒、银行扣款或账单同步。依据：pkg/models/transaction_template.go:14、:25；pkg/cron/cron_jobs.go:23；pkg/services/transactions.go:3207。常见用途为固定房租、固定订阅费等。

用户已确认首版关闭自动定时记账，保留普通手动模板。关闭创建/编辑自动定时交易的入口，服务端拒绝新增或启用自动定时模板，同时关闭后台自动生成任务；不能仅隐藏按钮。沿用现有配置开关关闭 enable_scheduled_transaction 和 enable_create_scheduled_transaction，实施时核验接口与任务实际行为。备份、过期令牌清理等其他定时任务照常运行。今后若启用自动记账，须另行补充成员停用时暂停、恢复时不自动补记的策略；不纳入首版。

### 独立维护

固定一个经过检查的上游提交作为起点，不定期合并上游功能更新。持续关注上游安全公告和相关依赖问题，按实际风险单独移植安全修复；维护自己需要的依赖与浏览器兼容。保留上游来源、MIT许可、基线SHA和安全修复来源记录。

此前已核验稳定提交v2.1.1 / 3dcc316e1fb6a190d6a0dd13fbe4052d17b9315c可作为候选；当前工作树为82920c62的开发主线。冻结实现基线前核对两者差异与已知问题，不能将本轮讨论当作已经切换分支、完成安全补审或保证基线无漏洞。

日常按月留出0.25–0.5人天检查依赖/安全公告、备份结果、磁盘和基本登录；这是建议预留，不是实际测得维护成本。无变化不为追赶版本而升级；有关键修复时单独估算、验证再发布。完全不看上游并不推荐。

### 保留的最低质量要求

- 强随机密钥、公网TLS、关闭公开注册、不打印密码/令牌/验证码，代理信任仅实际入口。
- 登录、取数及附件均需认证；只有当前启用成员可读家庭；任何普通成员不能写他人的账户/交易。
- 一笔金额保存正确，统计类型/货币/周期正确，重试不重复记账。
- 字典引用可解析，已有引用不能被误删；个人导入导出、模板、定时交易等关键入口不因共享字典损坏。
- 备份可恢复；依赖告警需检查和处置，不把未执行扫描当作通过。

不为家庭场景要求大型权限平台、高并发架构、通用迁移框架或专业全源码审计；此前有限安全审查中发现的实际问题仍需判断和处理。全源码通读、逐依赖实现审计与发布镜像比对未完成，不再列为首阶段全面审计交付，也不能对外声称已完成。

此前完整方案57/95/153人天已经失效，不再用作当前项目预算。本轮主要减少的是家庭生命周期、细粒度授权、旧库迁移、三库兼容、历史汇率、跨成员匹配和双端对等体验。

最大不确定项：共享字典对原有入口的穿透程度；选用稳定基线与本地开发版本认证差异；Pocket ID实际claim/绑定和移动会话表现；已知依赖告警所需修复量。遇到这些问题先缩小修复范围，不扩展为无关重构。专业全源码/逐依赖人工安全审计、自动异地灾备、未来新功能和突发安全事件修复不含在此估算内。

# 家庭报表架构

## 状态

已实现，随下一次独立 Android/Webapp 发布一起验收；旧家庭概览接口继续兼容。

## 数据边界

- `GET /api/v1/family/report.json` 按月或自然年、成员范围在服务端聚合，返回收支总览、日序列、分类及上期分类值、成员和账户。
- `GET /api/v1/family/report/transactions.json` 是报表点击后的只读明细源，支持成员、日期、分类、账户和稳定游标。
- 家庭报表只统计 CNY 的收入/支出，家庭内部转账不计入；外币只返回排除提示和笔数。
- Android 使用与个人报表相同的图表、分类环图、表格和加载/错误状态组件；家庭明细只读，自己的交易仍从个人流水编辑。

## 性能与兼容

- Android 冷启动不再预加载旧家庭概览和首页家庭流水；进入家庭页才请求报表。
- 服务端使用 SQLite 聚合查询，金额使用整数/十进制字符串，不在客户端加载全量历史账单。
- 旧 `/family/overview.json`、`/family/transactions/list.json` 和导出接口保留，避免影响交易提交身份校验及已有客户端。
- 新接口的成员范围会同时影响汇总、图表、分类、日报表、账户和明细，不允许只筛选流水。

## 验收基线

- 报表首屏目标：两名并发用户 P95 小于 1 秒；明细首屏 P95 小于 1.5 秒。
- 后端覆盖 SQLite 金额精度、成员范围、外币/内部转账排除和明细读取；Android 覆盖 JSON 到共享报表模型、月/年序列和金额精度。
- 模拟器验收对照个人报表：家庭页不再有独立“家庭流水”卡片，四个核心报表区块使用相同布局和交互。

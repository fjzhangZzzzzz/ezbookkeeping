## 1. 是否继续 fork

建议有条件继续，小家庭限定场景可行。保留个人账户/交易归属，只对家庭字典引用和独立聚合服务扩展。最难的是引用生命周期、权限与统计口径，而非增加 family 表或图表。不要先全面扩展 uid 查询再逐个补授权。

主线开发版本不等于最新稳定版：本地 `82920c62` 为标称2.2.0开发代码，当前可核验最新稳定为 `v2.1.1` / `3dcc316e1fb6a190d6a0dd13fbe4052d17b9315c`。建议以此稳定标签重新建立家庭开发分支，再逐项复核审计差异；不在本次评估切换/重置用户分支。公开TOTP完整修复需要≥2.1.0，但这只是已确认公告的版本下限，JSON/XML DoS首个修复版本未确认，不存在已证“所有漏洞都修复”的最低版。开发前对最终基线重新审计、跑工具和三库兼容测试。

如果只需要全家收支概览，无须改字典和日常记账，可评估独立只读统计层，减少个人功能改动；代价是数据同步、隐私授权和统一分类映射仍需维护。若期待多人共用账户、AA与债务结算或多人并行编辑同一交易，当前需求和上游模型不适合，应重新选型。本次没有对替代产品做源码评测，因此不提出具体产品优劣结论。

## 2. 风险登记册

概率为设计阶段判断，不是实测频率；“上游”仅指本次读取的本地上游快照。

| 类别/风险 | 概率 | 影响 | 缓解措施 | 验收方式 |
|---|---|---|---|---|
| 上游：开发主线与稳定tag不同 | 高 | 审计结果不能外推版本 | 固定稳定commit并重新检查差异 | tag→commit→镜像摘要可追溯 |
| 上游：默认secret回退 | 中 | 会话/敏感加密保护受损 | 强随机独立密钥，启动拒绝默认值 | 缺密钥无法启动，轮换演练 |
| 上游：CSV公式、query/TOTP日志 | 高 | 用户数据执行/泄漏 | 导出中和公式；日志脱敏 | Excel/LibreOffice与日志负测 |
| 上游：依赖审计未闭环 | 高 | 漏洞或供应链投毒 | 锁定、可达性分析、更新并重扫 | 工具成功且告警逐项处置 |
| N1 改造：scope扩大/IDOR | 中 | 整家庭/跨家庭泄漏 | 个人self固定，统一家庭scope/DTO | 每个资源域越权矩阵 |
| N2 改造：邀请枚举/并发超额 | 中 | 未授权入会 | 随机码哈希、限流、原子消费 | 同码并发只成功限定次数 |
| N3 改造：只读角色写接口 | 中 | 字典与成员被改 | service事务内重验角色 | 直调HTTP/CLI/任务入口 |
| N4 改造：共享删除/合并/退出引用 | 高 | 历史交易不可解释 | 软删、映射、分离任务 | 退出后个人统计/导出不丢项 |
| N5 改造：聚合扫描放大DoS | 中 | 单主机服务失效 | 成员/跨度/桶/导出限额 | EXPLAIN+并发压测+超时 |
| N6 改造：审计副本含敏感信息 | 中 | 新的泄漏副本 | 只存字典前后值、owner读取、留存 | 无金额/凭证/令牌/明细 |
| N7 改造：合并覆盖安全修复 | 高 | 已修漏洞复发 | GHSA追踪+安全回归固定样例 | 每次升级复跑修复用例 |
| 改造：时间游标跨uid漏页 | 高 | 汇总遗漏/金额错误 | 复合游标或逐uid聚合 | 相同transaction_time跨用户大于一页 |
| 改造：固定汇率缺失/错误精度 | 高 | 历史数字漂移 | 不可变快照、缺失阻断、有理数 | 零/二/三位币种、负数舍入 |
| 改造：聚合可反推个人隐私 | 中 | 小样本/差分透露单笔金额 | 限制组合筛选、默认仅汇总、本人同意 | 最小家庭2人差分评审 |
| 运维：代理IP信任过宽 | 中 | 白名单/日志绕过 | 仅信实际代理、拒绝绕过入口 | 直连伪造XFF/链式代理测试 |
| 运维：同故障域备份 | 中 | 主机与备份同时丢失 | 延续已知限制，离线副本另行决策 | 真正隔离恢复；不以健康代替 |
| 运维：退出后旧导出副本 | 高 | 已导出内容无法撤回 | 明示分享含下载后不可撤销 | UI说明与最少导出字段 |

## 3. 权限测试矩阵

| owner字典增改删/合并 | 家庭允许 | 本家庭共享允许 | 拒绝 | 拒绝 |

## 4. 正确性、兼容与并发用例

| 类别 | 必测样例 | 判定 |
|---|---|---|
| 统计 | 收10000，支4000，退款-500，余额调整+999 | 收10000/支3500/净6500，调整排除 |
| 本人转账 | 转出/入两条，币种相同与不同 | 收支都不变；转账流量仅计一对 |
| 跨成员往来 | A支500/B收500但无关联 | 不假定去重；明确不支持自动识别 |
| 汇率 | JPY→CNY、USD→CNY、三位精度币、极大/负金额 | 整数/有理数，无float误差；各维度勾稽 |
| 快照 | 次日刷新网络汇率、修改本位币、补录旧日交易 | 旧快照不漂移，冻结币种；缺失阻断 |
| 时间 | 跨月、跨年、闰日、UTC±边界、DST、周首 | 半开区间无丢失/重复，个人语义不变 |
| 游标 | A1/A2相同transaction_time且超过page size | 无漏页、无重复，任意页大小总数相同 |
| 字典 | 改名、软删、跨父移动、跨类型/域合并、别名环 | 合法重述/墓碑显示，非法拒绝 |
| 退出 | 有交易/标签索引/模板/定时模板/预设/别名引用 | 全部转为个人可解析，其他成员不受影响 |
| 隐私 | 私有分类命名为敏感文本 | 默认家庭DTO/CSV不含名称、原ID或标签 |
| 导入导出 | 上游原生格式、支付宝/微信、私有与共享同名 | UID不扩大；个人导出可独立恢复，不把family管理状态混入旧格式 |
| 迁移 | 0.7.x/1.2.x/2.0.x真实schema副本→固定稳定→家庭版 | 三库分别核对笔数/余额/附件/引用；不能只伪造version字段 |
| 空家庭/零交易 | 成员不足/无收支/仅转账 | 0或明确空态，无除零/NaN |
| 并发 | 同version改分类、改组/删标签与记账竞争 | 仅一个更新成功，其他409或明确重试 |
| 邀请 | 100并发消费1次码、同时加入两个家庭/最后容量 | 原子限次、N=1唯一、人数不超上限 |
| 成员竞争 | 退出与写字典/统计/导出同时发生 | 写事务重验；撤权后新请求不得命中旧scope缓存 |
| 恢复 | 数据库+图片+密钥+准确镜像恢复至隔离网 | 行数、余额、家庭权限、审计、图片均可验 |

性能基线待实测：2/5/10成员×每人1万/10万交易，测试31天/366天、冷热缓存、10并发统计与导出同时记账。记录数据库版本、主机规格、EXPLAIN(ANALYZE)、p50/p95、内存、锁等待与超时。建议初始交互p95≤2秒（10×10万数据、31天）、大跨度≤5秒，作为待基准确认目标而非已达承诺。禁止生产跑攻击或压力实验。

安全负测：SQL过滤/排序参数注入；XML实体及深度/JSON深度/超长数值；zip炸弹/XLSX解压、上传扩展/MIME/超大像素/路径穿越；CSV以=,+,-,@、tab/CR和全角特殊字符开头；HTML昵称/字典/审计diff的XSS；匿名/过期/重放TOTP；API刷新、伪造XFF、SSRF到127/169.254/IPv6/重定向；邀请限流不能只按可伪造IP；CSRF与跨源鉴权负测。明确新增家庭接口未实现，因此以上均为待执行用例。

## 5. homelab 部署设计

本轮只读本地 homelab-infra 声明，没有 SSH、实时健康/资源测量或部署。证据路径相对 `C:/Users/fjzha/Projects/homelab-infra`：`inventory/hosts.yml:60` 定义 control-01（amd64、控制/构建/备份角色），`:14` 定义 edge-01（公网入口）；`inventory/services.yml:398` 的必测备份集合当前没有ezbookkeeping或PostgreSQL；`docs/runbooks/recovery.md:3` 明确同故障域、RPO/RTO为目标。不能因已有Restic就声称本产品已获备份。

推荐应用+独立PostgreSQL Compose置于control-01，edge-01的Caddy只反向代理至受限EasyTier地址。数据库不发布宿主端口；应用仅绑定明确私网IP，并仅准入网关/管理来源。先确认端口、域名、磁盘/内存和CPU余量，不能凭清单推断运行容量。若采用仅家庭网访问，可先不加公网域名；已有Pocket ID不是默认获得ezBookkeeping原生用户授权的依据，OIDC为后续独立接入与账号绑定验收。

正式部署仍由homelab-infra的Ansible入口执行，版本、镜像来源/架构/摘要入 artifacts.lock.json，服务依赖/备份范围入 services.yml，配置入stacks和SOPS。应用源码/业务测试留在本fork，不在infra仓库新建自写备份发布器或另一套服务维护面板。运行目录沿用 `/etc/homelab/ezbookkeeping`、`/var/lib/homelab/ezbookkeeping`、`/var/log/homelab/ezbookkeeping` 与 `/srv/homelab/ezbookkeeping/current`；数据库状态需独立受限路径及版本化恢复依据。

Compose验收要求：准确镜像digest（不用latest）；非root且匹配挂载UID；read_only根fs+必要tmpfs/数据卷；drop capabilities/no-new-privileges；内存/PID/CPU/日志限制；DB就绪与业务就绪分开；数据库最小权限账户；健康端点不含账目/密钥；生产debug/SQL完整日志关闭。secret_key、DB密码、SMTP/OIDC配置只经SOPS/受限文件注入，不打印env；网关TLS，应用可信代理只填实际代理地址，覆盖默认私网大段信任。

外联默认最小化：AI/MCP/公开注册关闭；地图、SMTP、外部认证与汇率源按需求明确开启。前端依赖/字体打入本地工件，不依赖CDN。固定汇率可完全手动维护；选择国内可达公开源须另做实测及许可核验，不将网页可访问当作服务器可用证明。不新增SaaS遥测或监控。

### 备份/恢复与E3交付边界

本次是评估，不实现“一键脚本”。开发阶段应把一键动作加入现有 `ansible/backup.yml` / `restore.yml` 的产品配置，而非引入第二套备份机制。PostgreSQL用一致性pg_dump（与数据库主版本兼容）或停写完整卷备份；图片/附件与DB在同一停写窗口捕获，包含家庭/审计/汇率/迁移表、密钥、固定镜像和schema版本。不能在线复制PG数据目录冒充一致性备份。

向唯一必测集合注册后运行同一Restic流程。恢复先固定工件/摘要→隔离网络→数据库/附件/密钥同一快照恢复→校验→权限负测→由获准窗口切换；旧生产和新实例禁止并行处理定时交易。密钥不丢才能恢复加密字段；age私钥继续离线保管且不入自身备份。备份包含密钥/审计敏感数据，限制访问与留存，恢复完成后按既有手册处理验证环境。RPO24h/RTO1天须经该产品演练，不能继承其他服务结论。

## 6. 上游同步与CI

计划增加 upstream 只读远程、固定稳定tag，业务分支feature/family分组提交：schema→scope→字典→聚合→UI→测试→运维。先在临时集成分支merge新稳定版，经源码审查/权限回归/三库迁移/恢复演练后发布；安全修复可先cherry-pick但记录GHSA/CVE、上游SHA、fork SHA与测试。保留原MIT许可与版权。

冲突高发：cmd/webserver.go、pkg/services/transactions.go、transaction_categories/tags/templates、pkg/models字典/交易、数据初始化、src/stores与桌面/移动记账表单。新增家庭API/service独立文件，保持上游个人API与self过滤，减小合并面积。每次合并重新比对token类型门禁、TOTP重放和可信代理，不以文本无冲突代表安全。

CI建议：固定Go/Node与动作SHA；go.sum和package-lock.json入库；隔离缓存中go mod verify→govulncheck→三库构建/关键测试；npm ci --ignore-scripts后人工允许必要构建脚本→npm audit含开发依赖→类型与单元测试；用成熟SBOM工具输出Go/npm/镜像清单，保存扫描器版本/日期/告警处置；源码自建镜像且基础镜像digest锁定，记录commit与构建证明。不能用npm audit fix --force自动改变大量依赖后直接发布。扫描工具无法运行时CI失败或明确门禁阻断，不将“未执行”视为无漏洞。

## 7. 交付与决策门槛

当前可做的是技术路线评审。用户已确认家庭规模、个人模式、默认汇总/本人授权和退出撤权。进入实现前仍应确定：R16是否必须首期、是否要求历史成员报表永久稳定、是否需要金额级隐私和跨成员往来识别；补完当前源码与拟采用稳定基线间的安全差异审查。进入家庭生产前必须完成所有权限拒绝用例、三库迁移验证、导入导出兼容、供应链告警处置和本产品独立恢复演练。

这份评估不提供“完全无后门”的证明；全量源码逐文件人工通读、所有依赖逐包核查、发布二进制和容器内容比对仍需补审。公网对外提供服务会扩大合规/滥用场景，应另行评审，不计入家庭自托管估算。
